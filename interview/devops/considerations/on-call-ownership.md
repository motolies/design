# 새벽 장애의 담당팀과 운영 권한이 불명확하다

[이 폴더 목차](README.md) · [전체 진행 방법](../../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| 온콜 · 책임 경계 · 사고 소통 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 새벽에 담당 서비스가 아닌 경보가 울렸습니다. 개발팀은 직접 운영 권한을 달라고 하고 온콜 담당자는 피로를 호소합니다. 지금과 다음 주에 각각 무엇을 하겠습니까?

### 2.1 상황 상세

새벽 온콜을 맡고 있는 운영 엔지니어라고 가정합니다. 장애 경보가 발생하면 대응할 담당자에게 전달되고 필요한 조사가 시작되어야 합니다. 그런데 본인이 담당하는 서비스가 아닌 다른 서비스의 경보를 받았습니다.

경보를 받았다는 사실만으로 그 서비스의 대응을 누가 맡고 있는지까지 확인된 것은 아닙니다. 개발팀은 문제에 직접 대응할 수 있도록 운영 권한을 달라고 요청하고 있고, 온콜 담당자는 대응 부담과 피로를 호소하고 있습니다. 현재 눈앞의 경보 대응과 앞으로의 역할·권한 분담을 함께 다뤄야 하는 상황입니다. 지금 누구와 어떤 사실을 확인해 대응을 이어갈지, 다음 주에는 어떤 운영 방식을 논의할지 정해야 합니다.

## 3. 면접관용 추가 정보

고객 오류가 증가하고 있으나 서비스 소유자 목록이 오래됐습니다. 조회 권한은 있지만 변경 권한은 별도입니다. 사고 지휘자와 대외 안내 담당도 정해져 있지 않습니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 동일한 경보 오배정이 반복되고 한 담당자가 로테이션에서 빠지고 싶어 합니다. 장애 후에는 서로 책임을 묻는 분위기가 생깁니다.

## 4. 기본 답변 예시와 해설

현재 영향과 시간대를 기록하고 담당자를 호출하면서 권한 내 안전한 완화를 지원합니다. 지휘·복구·고객 소통 역할을 정하고 일정 간격으로 사실과 다음 확인 시간을 공유합니다. 상시 관리자 권한보다 필요 범위·기간의 접근과 감사 기록을 마련합니다. 이후 소유권·경보 라우팅·로테이션·휴식과 개선 담당자를 정하고 실행 결과를 추적합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| 내 담당이 아니라 끕니다 | 소유자가 응답할 때까지 사용자 영향은요? → 반복 오배정의 원인은요? | 초기 triage와 책임 인계를 구분하고 서비스 카탈로그·라우팅 테스트를 제안한다. |
| cluster-admin을 줍니다 | 조회와 변경 중 무엇이 필요한가요? → 긴급 권한 회수는요? | 최소 권한·시간 제한·승인 책임·감사와 self-service 안전 경로를 설계한다. |
| 모든 운영을 DevOps가 맡습니다 | 앱 오류의 지식과 책임은 어디에 있나요? → 팀이 계속 떠넘기면요? | 개발/플랫폼의 공동 운영 기준·에스컬레이션·교육을 합의한다. |
| 실수한 사람을 교육합니다 | 왜 실수가 전체 장애가 됐나요? → 개선 항목 완료는 누가 확인하나요? | blameless 타임라인과 시스템적 조건을 분석한다. 온콜 부하·알람 수·회복 시간·휴식으로 개선을 확인한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 현재 영향 완화와 담당자 인계를 우선한다. |
| 깊이 있는 이해 | 권한·소유권·피로·포스트모템 개선을 함께 운영한다. |
| 추가 확인 필요 | 비난하거나 책임 경계만 강조해 대응을 멈춘다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
