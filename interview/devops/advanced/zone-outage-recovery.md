# 멀티 AZ인데 한 영역 장애로 서비스가 멈춘다

[이 폴더 목차](README.md) · [전체 진행 방법](../../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| 가용성 · 저장소 · 재해 복구 · 카오스 실험 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 멀티 AZ로 구성했는데 한 AZ가 중단되자 서비스 전체가 멈췄습니다. 복구와 재발 방지 계획을 어떻게 세우겠습니까?

## 3. 면접관용 추가 정보

앱은 여러 AZ에 있지만 DB와 일부 NAT·스토리지 의존은 한 AZ에 있습니다. 목표는 RPO 30분, RTO 1시간입니다. 백업은 있으나 최근 복원 시험 기록은 없습니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: Pod를 다시 띄워도 볼륨에 접근하지 못합니다. 경영진은 운영 장애 실험에 반대하고 있습니다.

## 4. 기본 답변 예시와 해설

실제 의존 경로와 장애 영역을 그리고 살아 있는 AZ의 용량·네트워크·DB·볼륨 접근을 확인합니다. 백업 시각과 복원 소요를 측정해 목표와 비교합니다. RPO는 허용 데이터 손실, RTO는 서비스 복구 시간으로 나눕니다. 백업 존재만으로 목표 충족을 주장하지 않고 데이터 검증과 트래픽 전환까지 복구 훈련합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| Pod를 다른 AZ에 띄웁니다 | 볼륨도 그 AZ에서 붙나요? → StatefulSet이 복제를 보장하나요? | PV/PVC·스토리지 topology·복제와 백업 책임을 구분한다. 컨테이너 DB도 가능하지만 운영 책임이 사라지지 않는다. |
| 백업을 복원합니다 | 마지막 성공 백업과 실제 복원 시간은요? → 애플리케이션 검증 시간도 포함했나요? | 복원·재생·정합성 확인·DNS/LB 전환까지 목표를 검증한다. |
| 카오스 실험을 합니다 | 중단 기준과 폭발 반경은요? → 운영에서 거부되면요? | 정상 상태 가설·스테이징 실험·제한된 대상·복구 담당자·자동 중단을 단계적으로 제시한다. |
| runbook을 작성합니다 | 처음 보는 온콜도 실행 가능한가요? → 문서가 낡았는지는요? | 증상·진단·조치·검증·중단/연락 조건과 소유자·마지막 훈련 시점을 기록한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 앱 복제와 하위 의존의 장애 영역을 구분한다. |
| 깊이 있는 이해 | RPO/RTO를 복원 훈련으로 측정하고 실험 범위를 통제한다. |
| 추가 확인 필요 | 멀티 AZ나 백업이 있으니 자동으로 복구된다고 한다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
