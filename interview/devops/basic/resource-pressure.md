# 서버 자원 경보와 재시작이 반복된다

[이 폴더 목차](README.md) · [전체 진행 방법](../../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| Linux · 컨테이너 · 증거 기반 진단 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 서비스 지연과 함께 자원 경보가 울리고 일부 프로세스가 재시작됩니다. 재시작하면 잠시 회복합니다. 첫 조사 순서와 안전한 완화 조치를 설명해 주세요.

## 3. 면접관용 추가 정보

VM의 systemd 서비스와 Kubernetes Pod가 함께 있습니다. CPU·메모리·디스크 지표와 종료 코드, 이전 로그를 볼 수 있습니다. 한 노드는 load average가 높지만 CPU는 낮고, df와 du 사용량도 다릅니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 137 종료 코드가 발견됩니다. 컨테이너 안 top 수치와 플랫폼 지표가 다르며 디스크 inode도 부족해집니다.

## 4. 기본 답변 예시와 해설

영향·시작 시각·변경 사항을 확인하고 프로세스/컨테이너별 사용량과 제한을 나눕니다. top/ps/pidstat로 CPU, vmstat/iostat로 대기, df/du/df -i로 공간과 inode를 확인합니다. 삭제됐지만 열린 파일은 lsof +L1로 찾습니다. 종료 코드만으로 원인을 확정하지 않고 OOMKilled reason·커널/cgroup 이벤트·이전 로그를 대조합니다. 완화 후 사용자 지연과 자원 추세가 회복됐는지 확인합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| CPU가 낮아 정상입니다 | load에 어떤 작업이 포함되나요? → D 상태 작업을 kill하면 끝나나요? | 실행 가능 작업과 uninterruptible 대기를 구분하고 I/O 지연·시스템 호출을 확인한다. |
| 137이므로 메모리를 늘립니다 | 누가 SIGKILL을 보냈나요? → 호스트와 cgroup 제한은요? | 137은 SIGKILL 단서이며 OOM의 단독 증거가 아니다. 143/SIGTERM과 구분하고 제한·사용량·노드 압박을 본다. |
| 로그를 삭제합니다 | 열린 fd 공간은 회수되나요? → inode와 log rotation은요? | 삭제/핸들 해제와 공간 회수를 연결하고 보존 정책·회전·수집기 적체를 다룬다. |
| 서비스를 재기동합니다 | systemd 상태와 직전 로그는요? → 컨테이너 runtime은 누가 관리하나요? | unit의 ExecStart/User/Restart, daemon-reload/enable/start/status, journalctl을 목적과 연결한다. namespace 격리와 cgroup 자원 제어, VM 경계, Docker/containerd/runc 역할을 구분한다. |
| 추적 도구를 붙입니다 | strace나 tcpdump가 장애를 키우지 않을까요? → TLS 안의 내용을 볼 수 있나요? | ss·프로세스·시스템 호출·패킷 증거를 선택하며 필터·시간·크기·민감정보 접근을 제한한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 프로세스·호스트·컨테이너 자원과 종료 증거를 나눈다. |
| 깊이 있는 이해 | 복구 비용을 고려해 증거를 확보하고 원인별 완화를 검증한다. |
| 추가 확인 필요 | kill -9와 limit 증설을 모든 상황에 반복한다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
