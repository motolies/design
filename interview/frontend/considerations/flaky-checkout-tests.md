# 테스트는 자주 실패하지만 결제 버그는 놓친다

[이 폴더 목차](README.md) · [전체 진행 방법](../../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| 테스트 전략 · 회귀 검증 · 멘토링 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 결제 화면 E2E가 매일 실패해 팀이 재실행만 하고 있습니다. 그런데 실제 결제 오류는 테스트를 통과했습니다. 다음 주에 쓸 수 있는 개선안을 제안해 주세요.

### 2.1 상황 상세

결제 화면의 자동 테스트와 출시 검증을 담당한다고 가정합니다. 결제 화면 E2E 테스트는 사용자가 화면을 조작해 결제하는 흐름이 정상인지 확인하는 수단입니다. 기능이 정상일 때는 신뢰할 수 있는 성공 결과를 주고, 사용자 결제를 막는 결함이 있으면 출시 전에 발견하는 것이 기대입니다.

현재는 테스트 실행 기록에 매일 실패가 나타나고, 팀은 실패 원인을 확인하는 대신 재실행하는 일을 반복하고 있습니다. 그런데 테스트를 통과한 변경에서도 실제 사용자의 결제 오류가 발견됐습니다. 테스트 실패가 모두 제품 결함을 뜻하는지와 실제 결제 오류를 놓친 이유는 아직 구분하지 않았습니다. 실행 결과와 실제 오류 사례를 어떤 기준으로 비교하고, 다음 주부터 적용할 개선 범위를 어떻게 정할지 결정해야 합니다.

## 3. 면접관용 추가 정보

애니메이션과 임의 sleep, 공유 테스트 계정, 외부 결제 sandbox 의존이 있습니다. 컴포넌트 단위 검사는 적고 스크린샷은 매번 전체 갱신합니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 테스트 비용을 절반으로 줄여야 합니다. 신입에게 테스트 작성과 AI 코드 검증도 맡겨야 합니다.

## 4. 기본 답변 예시와 해설

최근 실패를 제품 결함·테스트 격리·환경 문제로 분류합니다. 핵심 결제 상태 전이와 오류 복구는 통합 테스트로, 실제 연결은 소수 E2E로, 순수 계산은 단위 테스트로 분리합니다. 데이터·시간·네트워크를 통제하고 관찰 가능한 완료 조건을 기다립니다. 시각 회귀는 주요 결제 상태·공통 컴포넌트에 집중하고 baseline 변경을 사람이 검토합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| 재시도를 늘립니다 | 실제 결함도 숨기지 않나요? → 격리 테스트의 복구 기한은요? | 실패율·소유자·원인·격리 만료와 재현 조건을 관리한다. |
| 커버리지 100%를 목표로 합니다 | 중복 결제 방지나 실패 복구가 검증됐나요? → 첫 테스트는요? | 위험한 사용자 행동을 먼저 고른다. 줄 커버리지와 업무 검증을 구분한다. |
| 스크린샷으로 대체합니다 | 금액이 서버에 잘못 전달된 것도 잡나요? → 무엇을 E2E에 남기나요? | 시각적 변화와 의미·통신·접근성 검증의 책임을 구분한다. |
| 신입에게 전부 맡깁니다 | 실패 원인을 설명할 수 있도록 어떻게 돕나요? → 자동화 유지비가 더 크면요? | 페어링·작은 검증 목표·리뷰 피드백과 자동화 손익 기준을 제시한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 불안정한 환경과 제품 결함을 나누고 핵심 흐름을 선정한다. |
| 깊이 있는 이해 | 비용·신뢰도·회귀 탐지력을 측정하며 신입의 설명 능력을 확인한다. |
| 추가 확인 필요 | 통과할 때까지 재시도하거나 기준 이미지를 일괄 승인한다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
