# AI가 만든 코드를 이해하지 못한 채 머지하려 한다

[이 폴더 목차](README.md) · [전체 진행 방법](../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| AI 검증 · 보안 · 학습 · 책임 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 동료가 AI로 만든 변경을 올렸습니다. 테스트는 통과하지만 동작 원리를 설명하지 못합니다. 마감은 오늘입니다. 어떤 확인을 거쳐 머지 여부를 판단하겠습니까?

## 3. 면접관용 추가 정보

변경에는 애플리케이션 코드와 배포 설정이 포함됩니다. 테스트도 같은 AI가 생성했습니다. 프롬프트에 내부 오류 로그 일부를 넣었다고 합니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 존재하지 않는 라이브러리 옵션이 발견됩니다. 팀은 AI 도입 효과와 사용 가이드도 요청합니다.

## 4. 기본 답변 예시와 해설

변경 의도·입출력·실패 경계·권한을 작성자가 설명하게 하고 실제 의존성 버전과 공식 문서를 대조합니다. 독립적인 요구 기반 테스트·정적 검사·작은 재현으로 생성 테스트의 빈틈을 확인합니다. 프롬프트의 비밀·개인정보·내부 코드 전송 범위와 회사 승인 정책을 확인하고 노출 시 정해진 절차로 처리합니다. 이해할 수 없는 범위는 줄이고 검증 책임자를 명확히 합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| 테스트가 통과했으니 머지합니다 | 테스트가 같은 잘못된 가정을 복제하면요? → 실패 입력을 직접 고르면요? | 독립적인 기대값·경계 사례·실제 실행으로 검증한다. FE는 접근성/렌더, IaC는 plan/권한/삭제 영향을 확인한다. |
| AI 사용을 금지합니다 | 어느 단계에서 도움이 됐나요? → 직접 하는 편이 빠른 경우는요? | 초안·리뷰·문서·반복 작업의 이득과 검증 비용을 비교한다. 사고 시 판단과 책임을 사람에게 둔다. |
| 내부 도구라 입력해도 됩니다 | 저장·학습·보존 정책을 확인했나요? → 코드 출처가 불명확하면요? | 승인된 서비스·최소 입력·마스킹·접근 권한·라이선스 검토 경로를 구분한다. 정책을 추측하지 않는다. |
| 선임이 대신 고칩니다 | 작성자는 다음에 어떻게 독립적으로 검증하나요? → 도입 효과는요? | 작은 변경 설명·페어 디버깅·공식 문서 확인을 반복하고 절약 시간과 재작업·결함 비용을 함께 측정한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | AI 출력도 검토 대상이며 본인 설명과 실행 검증이 필요함을 안다. |
| 깊이 있는 이해 | 데이터 정책·독립 검증·주니어 학습·도입 효과를 함께 다룬다. |
| 추가 확인 필요 | AI나 선임에게 정확성 책임을 전부 넘긴다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
