# 리뷰 의견 충돌로 배포가 지연된다

[이 폴더 목차](README.md) · [전체 진행 방법](../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| 코드 리뷰 · Git · 멘토링 · 의사결정 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 리뷰어는 구조를 전부 바꾸자고 하고 작성자는 동작하니 머지하자고 합니다. 신입 작성자는 더 이상 리뷰받고 싶지 않다고 합니다. 어떻게 다음 행동을 정하겠습니까?

## 3. 면접관용 추가 정보

PR에는 기능·포맷·리팩토링이 함께 있습니다. 합의된 규칙은 적고 공유 브랜치에서 여러 사람이 작업합니다. 기능 자체의 실패 사례는 아직 제시되지 않았습니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 공유 브랜치 force push로 동료 커밋이 사라지고 리뷰 시간이 계속 늘어납니다. 팀의 개선 제안에도 반대가 있습니다.

## 4. 기본 답변 예시와 해설

정확성·보안·유지보수 위험과 취향을 분리하고 재현 사례·규칙·작은 실험으로 논의합니다. 반드시 수정할 부분과 후속 개선을 나눠 PR을 검토 가능한 단위로 줄입니다. 신입에게 의도를 먼저 묻고 이유와 대안을 설명하며 직접 수정·설명할 기회를 줍니다. 합의가 어려우면 결정권자·기준·재검토 조건을 기록하고 결과를 함께 검증합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| 선임 의견을 따릅니다 | 어떤 근거를 남기나요? → 본인 의견이 기각되면요? | 권위보다 판단 기준을 설명하고 결정 후 실행과 회고에 참여한다. |
| 모두 규칙으로 강제합니다 | 스타일과 설계 판단은 같나요? → 리뷰 순서는요? | 요구·테스트·실패 경계부터 보고 스타일은 도구로 처리한다. 작은 PR·응답 시간·페어 리뷰로 부담을 줄인다. |
| rebase로 정리합니다 | 공유 이력은 누가 참조하나요? → 사라진 커밋은요? | merge의 이력 보존과 rebase 재작성·squash·interactive rebase를 구분한다. reflog/동료 clone에서 복구 후보를 확인하고 추가 덮어쓰기를 멈춘다. |
| 프로세스를 바꿉니다 | GitFlow와 trunk 방식 중 지금 배포 주기에 맞는 것은요? → 미완성 기능은요? | 짧은 브랜치·릴리스 관리·플래그·테스트 조건을 비교한다. 반대 이유를 듣고 시범 적용의 리뷰 시간·결함을 측정한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 사람과 코드를 분리하고 확인 가능한 근거로 논의한다. |
| 깊이 있는 이해 | 멘토링·작은 변경·이력 복구·팀 규칙을 함께 개선한다. |
| 추가 확인 필요 | 강압·무조건 머지·공유 이력 재작성을 해결로 삼는다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
