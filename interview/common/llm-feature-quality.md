# AI 답변 기능의 품질과 비용을 합의해야 한다

[이 폴더 목차](README.md) · [전체 진행 방법](../README.md)

## 1. 빠른 안내

| 평가 역량 | 난이도 | 예상 시간 |
|---|---|---|
| LLM 기능 평가 · 제품 판단 · 실패 대응 | 기본 → 심화 | 기본 10~15분 / 심화 15~20분 |

<a id="basic"></a>

**기본 진행**: 상황과 첫 질문 → 확인 질문에 맞춰 추가 정보 제공 → 답변에 맞는 분기 1~2개 → 평가·경험 연결. 답변을 먼저 듣고 해설은 읽어주지 않습니다.

**심화 진행**: 같은 상황에서 기본 가설을 짧게 확인한 뒤 아래 심화 조건과 표의 `→` 뒤 질문을 선택합니다. 예상 시간은 기본과 심화를 합산한 시간이 아니라 각 진행 경로의 시간입니다. 모든 분기를 묻지 않습니다.

## 2. 지원자에게 읽어줄 상황과 첫 질문

> 고객 지원 답변 기능의 시연은 좋았지만 같은 질문에 답이 달라지고 없는 정책을 안내합니다. 출시를 계속할지 어떤 근거로 판단하겠습니까?

### 2.1 상황 상세

고객의 질문에 답하는 AI 기능의 출시 검토를 맡았다고 가정합니다. 고객은 서비스 이용 방법이나 정책을 물었을 때 실제 정책에 맞는 안내를 받아야 합니다. 시연에서는 자연스러운 답변을 보여 주어 기능에 대한 기대가 높아졌습니다.

그런데 같은 질문을 반복해 입력하자 답변 내용이 달라지는 경우가 있었고, 실제로 존재하지 않는 정책을 안내하는 답변도 확인됐습니다. 현재 관찰한 것은 입력한 질문과 출력된 답변의 차이, 그리고 정책과 맞지 않는 안내 사례입니다. 답변의 표현 차이와 고객에게 잘못된 행동을 유도할 내용 차이가 어느 정도인지는 아직 평가하지 않았습니다. 출시를 계속할지 판단하기 위해 어떤 사례와 기준으로 품질을 확인할지 정해야 합니다.

## 3. 면접관용 추가 정보

내부 도움말을 근거로 답해야 하며 고객 계정 정보 접근은 제한되어야 합니다. 응답 지연·호출 비용 예산이 있고 상담원 연결 경로가 있습니다.

정보가 없는 질문에는 정답을 추측해 주지 말고 지원자의 가정을 명시하게 합니다. 같은 면접에서는 합의한 조건을 유지합니다.

<a id="deep"></a>

**심화에서 추가할 조건**: 외부 문서에 지시문이 섞여 들어오고 응답 형식도 가끔 깨집니다. 모델이나 프롬프트 변경 후 회귀를 확인해야 합니다.

## 4. 기본 답변 예시와 해설

정확성·근거·거절·권한·지연·비용을 평가 항목으로 정하고 대표 질문과 실패 사례의 평가 세트를 만듭니다. 검색 근거와 답변의 일치 여부를 점검하며 권한 필터를 검색 전후에 적용합니다. 구조화 출력도 검증하고 불확실하거나 실패한 답은 상담원 연결로 전환합니다. 제한된 공개와 버전별 회귀 평가로 출시 여부를 결정합니다.

이는 가능한 접근의 예입니다. 다른 해법도 조건·선택 이유·실패 한계·검증이 연결되면 인정합니다.

## 5. 답변별 꼬리 질문

`→` 뒤는 앞 질문에 답했을 때 이어갈 한 단계 깊은 질문입니다. 모르는 답변에는 추가 조건을 하나 주고 추론이 어떻게 바뀌는지 확인합니다.

| 지원자 답변 또는 접근 | 다음 질문 | 확인할 핵심과 판단 근거 |
|---|---|---|
| temperature를 낮춥니다 | 사실 정확성도 보장되나요? → 같은 오류가 일관되면요? | 표현 변동과 사실성을 구분하고 근거 검증·평가 데이터로 판단한다. |
| RAG를 씁니다 | 오래된 문서나 권한 밖 문서는요? → 문서 속 지시문은요? | 검색 품질·최신성·권한 격리·prompt injection을 구분하고 외부 내용을 신뢰된 명령으로 취급하지 않는다. |
| 자동 평가로 통과시킵니다 | 평가 모델도 틀리면요? → 비용과 실패 기준은요? | 사람 검토 표본·업무 기준·오탐/누락·회귀 기록과 호출 제한·timeout·fallback을 정한다. |

## 6. 평가 기준

| 구분 | 관찰할 행동과 설명 |
|---|---|
| 기본 이해 | 평가 세트와 실패 시 사용자 경로를 제안한다. |
| 깊이 있는 이해 | 권한·근거·회귀·비용을 함께 검증한다. |
| 추가 확인 필요 | 프롬프트 하나나 RAG만으로 환각이 제거된다고 한다. |

기술명 언급 수로 점수를 매기지 않습니다. 답변에서 관찰한 근거, 제공한 힌트, 남은 불확실성을 따로 적습니다. 질문하지 않은 역량은 미평가로 남깁니다.

## 7. 실제 경험으로 연결

- 이 상황과 비슷한 경험에서 제약과 본인의 역할은 무엇이었습니까?
- 직접 내린 결정·수행한 검증과 동료의 기여를 구분해 설명해 주세요.
- 결과를 어떤 수치나 관찰로 확인했으며, 다시 한다면 무엇을 바꾸겠습니까?

직접 경험이 없으면 유사한 학습·실험 경험 또는 이 상황의 검증 계획으로 이어갑니다.
